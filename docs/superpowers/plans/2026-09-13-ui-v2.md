# EpiSignal UI v2 implementation plan

**Goal:** Implement the user-approved UI v2 specification without changing backend behavior or accessing production.

**Architecture:** Preserve the dashboard and event-detail API adapters and MapLibre map. Share navigation, theme, URL filters, summary, and source components across the map, briefing, and server-rendered event detail. Use existing Fraunces and Inter fonts, neutral tokens, and Lucide icons. The supplied specification defines the approved observable testing seams.

**Spec:** [User specification](../specs/2026-09-13-ui-v2-design.md)

**Baseline:** `198964ab5041666ac0490e09c4fe02904aeb348f`, branch `codex/next-iteration`.

- [ ] 6. Review and QA: independent standards/spec reviews against baseline; fix actionable findings. Inspect all three routes at desktop/mobile in white/black with local fixtures, long headlines, one and seven sources, three/five bullets, legacy and unresolved content; save screenshots and check overflow. - [ ] 7. Record verification in STATUS and report, commit and push `codex/next-iteration`, verify remote HEAD and clean tree. No deployment, production, VPS or Coolify access.

## Boundaries and acceptance

No changes to API contracts, backend, prompts, data, migrations, scheduler, or monitoring. No new surveillance metrics. Source counts describe linked reporting, never inferred epidemiological milestones. Tests use local fixtures and mocked network only. Existing `/events` remains compatible; shared shell applies across routes. Planner owns this plan and handoff; implementation workers own source/tests. Review and verification follow implementation with no scope expansion.
